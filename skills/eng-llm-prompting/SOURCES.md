# Sources: prompt quality and layout

Fetched and read on 2026-10-26. **[V]** checked against the primary page that day, with the quoted wording; **[J]** a judgement threshold of this pack, not a source claim.

- P1 - Anthropic, **Prompting best practices** (platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices; the old system-prompts, xml-tags, long-context, multishot, chain-of-thought and prefill pages now redirect here) - 2026 - [V] - Long context: "Place your long documents and inputs near the top of your prompt, above your query, instructions, and examples"; "Queries at the end can improve response quality by up to 30 percent in tests, especially with complex, multidocument inputs" (for "large documents or data-rich inputs (20k+ tokens)"); `<document>` with `<document_content>` and `<source>` subtags; "ask Claude to quote relevant parts of the documents first". Examples: "Include 3–5 examples for best results", relevant, diverse, "Wrap examples in `<example>` tags (multiple examples in `<examples>` tags)". XML: "Use consistent, descriptive tag names across your prompts", nest tags for hierarchy. Context: explaining why an instruction matters helps more than "NEVER use ellipses". Prefill: "Starting with Claude 4.6 models ... prefilled responses ... on the last assistant turn are no longer supported. Requests with prefilled assistant messages to these models return a 400 error"; migrate format control to structured outputs, classification to "tools with an enum field ... or structured outputs". Chaining: self-correction (draft, review, refine) as separate calls when intermediate outputs must be inspected.
- P2 - Anthropic, **Prompt engineering overview** (platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview) - 2026 - [V] - prerequisites: "A clear definition of the success criteria", "Some ways to empirically test against those criteria", "A first draft prompt".
- P3 - Anthropic, **Define success criteria and build evaluations** (platform.claude.com/docs/en/test-and-evaluate/develop-tests) - 2026 - [V] - held-out test set in the success criteria; "Prioritize volume over quality: More questions with slightly lower signal automated grading is better than fewer questions with high-quality human hand-graded evals"; LLM grading tips: "Have detailed, clear rubrics", "Be empirical or specific" (correct/incorrect or 1-5), "Encourage reasoning: Use a grader model with thinking on".
- P4 - Anthropic Engineering, **Demystifying evals for AI agents** (anthropic.com/engineering/demystifying-evals-for-ai-agents) - 2026 - [V] - "LLM-as-judge graders should be closely calibrated with human experts to gain confidence that there is little divergence between the human grading and model grading"; "give the LLM a way out, like providing an instruction to return 'Unknown'"; "grade each dimension with an isolated LLM-as-judge"; "Test both the cases where a behavior should occur and where it shouldn't. One-sided evals create one-sided optimization"; pass@k vs pass^k; capability vs regression evals; read the transcripts.
- P5 - Anthropic Engineering, **Effective context engineering for AI agents** (anthropic.com/engineering/effective-context-engineering-for-ai-agents) - 2025 - [V] - "finding the smallest possible set of high-signal tokens that maximize the likelihood of some desired outcome"; system prompts at the "right altitude"; few-shot: "teams will often stuff a laundry list of edge cases into a prompt ... We do not recommend this. Instead, we recommend working to curate a set of diverse, canonical examples"; just-in-time retrieval with lightweight identifiers; compaction: "overly aggressive compaction can result in the loss of subtle but critical context ... Start by maximizing recall ... then iterate to improve precision"; tool result clearing as the lightest compaction; structured note-taking; sub-agents with clean context windows.
- P6 - Anthropic, **Context windows** (platform.claude.com/docs/en/build-with-claude/context-windows) - 2026 - [V] - "As token count grows, accuracy and recall degrade, a phenomenon known as context rot"; tool definitions, system prompt and every message count toward the window; cached tokens still occupy it; server-side compaction is "the primary strategy" for long conversations.
- P7 - Anthropic, **Compaction** overview and **Compaction at a token threshold** (platform.claude.com/docs/en/build-with-claude/compaction, .../compaction-threshold) - 2026 - [V] - compaction "replaces the older turns of a conversation with a summary that Claude writes on the server"; recent turns can be kept word for word; "add a `cache_control` breakpoint at the end of your system prompt ... The system prompt cache remains valid ... Only the compaction summary needs to be written as a new cache entry".
- P8 - Anthropic, **Tool search tool** (platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool) - 2026 - [V] - "~55k tokens in definitions"; "Tool search typically reduces this by over 85 percent"; "Claude's ability to pick the right tool degrades once you exceed 30–50 available tools"; use it at "10 or more tools" or definitions over "10k tokens"; "Keep your 3–5 most frequently used tools non-deferred"; deferred tools are excluded from the prefix and appended as `tool_reference` blocks: "The prefix is untouched, so prompt caching is preserved"; a deferred tool cannot carry `cache_control`.
- P9 - Anthropic, **Tool use with prompt caching** (platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching) - 2026 - [V] - invalidation table: tool definitions -> entire cache; web search or citations toggle -> system and messages; `tool_choice`, `disable_parallel_tool_use`, images present/absent -> messages cache; thinking parameters and `output_config.effort` -> messages always, tools and system on some models; "If you need to vary `tool_choice` mid-conversation, consider placing cache breakpoints before the variation point".
- P10 - Anthropic, **Thinking** (platform.claude.com/docs/en/build-with-claude/thinking) - 2026 - [V] - "The thinking configuration and the resolved effort level are rendered into the prompt itself, so changing any of them starts a new cache prefix"; "Blocks passed back unchanged keep the cache intact"; prefill rejected from Claude 4.6; forced tool use incompatible with manual extended thinking and rejected on some current models.
- P11 - Anthropic, **Prompt caching** (platform.claude.com/docs/en/build-with-claude/prompt-caching) - 2026 - [V] - "a single cache breakpoint at the end of your static content is sufficient ... If a later block varies with each request (a timestamp, the incoming message), keep the breakpoint before it"; the moving breakpoint for growing conversations and the 20-block lookback. Full cache mechanics are in `eng-llm-cost/SOURCES.md` (S8, S28-S33).
- P12 - Paired comparison with an interval (non-inferiority margin `prompt.quality_drop_max_pp`), Cohen's kappa for judge agreement (Cohen, "A coefficient of agreement for nominal scales", Educational and Psychological Measurement 20(1), 1960) - [J] for the margins; the statistics are standard.
