# Sources: Product agent loops and LLM features

Carried over from the research pass of 2026-10-25 (`02-research-agent-harness.md`), product-specific lines removed. Each line keeps the tag it had there: **[V]** checked against the primary page in that pass; **[K]**, **[B]**, **[C]** or **[M]** a known citation (author, year, venue) not re-opened; **[U]** unverified, treat as a hypothesis. Lines without a tag were cited with their venue and date only.

- Simplest solution first; add complexity only when measured to help - Stops guard/judge creep - Anthropic, "Building effective agents", 19 Dec 2024 [V]: "we recommend finding the simplest solution possible, and only increasing complexity when needed"
- Ablation / controlled experiment with effect sizes - Proves each layer earns its cost - Kohavi, Tang, Xu, *Trustworthy Online Controlled Experiments*, Cambridge UP 2020 [M]
- Pre-mortem - Lists failure modes before building - Klein, "Performing a Project Premortem", HBR Sept 2007 [M]
- FMEA - Ranks each failure mode by severity × occurrence × detectability - IEC 60812:2018 [M]
- Root cause instead of symptom (5 Whys; blameless postmortem) - Stops symptom patching - Ohno, *Toyota Production System*, 1988 [M]; Beyer et al., *Site Reliability Engineering*, O'Reilly 2016, ch. 15 [M]
- ADR (Architecture Decision Record) - Keeps the *why* so a later fix does not undo it - Nygard, "Documenting Architecture Decisions", 2011 [M]
- Checklists (read-do / do-confirm) - Pre-flight discipline - Gawande, *The Checklist Manifesto*, 2009 [M]
- Property-based testing - Invariants such as "never silently drop data" - Claessen & Hughes, "QuickCheck", ICFP 2000 [M]
- Golden sets, held-out sets, calibrated LLM judges - Evaluation that generalises - Zheng et al., "Judging LLM-as-a-Judge with MT-Bench", NeurIPS 2023 D&B [M]; Shankar et al., "Who Validates the Validators?", UIST 2024 [V]
- Specification gaming awareness - The fix meets the letter of the test and misses its intent - Krakovna et al., DeepMind blog, 21 Apr 2020 [V]
