- FMEA - Table per pipeline stage: failure mode × effect × detection × severity. Rank by RPN. The "detection" column forces a check for silent loss. - IEC 60812:2018 *Failure modes and effects analysis*.
- Formal spec / model checking - Specify the job/approval/step-cursor state machine and check safety ("never executed twice") and liveness ("eventually terminal") under crashes and interleavings. - Lamport 2002; Newcombe et al., *CACM* 2015.
- Linearizability / history checking - Record concurrent op histories in tests and check them against a sequential model (Knossos, Porcupine). - Herlihy, M. & Wing, J. "Linearizability." *ACM TOPLAS* 12(3), 1990; Kingsbury, K. Jepsen analyses (jepsen.io).
- Deterministic simulation testing - Run the scheduler with seeded fake time + injected crashes, so a failing interleaving is reproducible. - FoundationDB; Wilson, W. "Testing Distributed Systems w/ Deterministic Simulation." Strange Loop 2014 **[talk, not a paper]**.
- Chaos engineering - Kill workers, drop acks, delay heartbeats in staging. Hypothesis = steady-state metric unchanged. - Basiri, A. et al. "Chaos Engineering." *IEEE Software* 33(3), 2016.
- Sagas / compensation - Multi-step outward effects without a distributed transaction. Each step has a compensating action. - Garcia-Molina, H. & Salem, K. "Sagas." SIGMOD 1987.
- SLOs on freshness and completeness - SLIs: % jobs terminal within T, % webhooks persisted, duplicates per 10k. Error budget gates releases. - Beyer et al. 2016, ch. 4 "Service Level Objectives".
- Checklists - A short read-do list at design review (section 3) and a do-confirm list at PR (section 5). - Gawande, A. *The Checklist Manifesto*. 2009.
- ADRs - Record the delivery semantics, retry owner and idempotency key per flow, so later agents do not re-decide. - Nygard, M. "Documenting Architecture Decisions." 2011-11-15.
