# Worker clause

Paste at the end of every coding agent's prompt while a train runs; fill the orchestrator id.

---

Shipping (train system):
- Before your first edit, class the task and write `<worktree>/.agent/preflight.md` (the jstack hook reminds you on the first edit and names the signals). **quick** (hotfix, quick fix, copy or style, config): one line `class: quick - <why>`, nothing else. **light** (ambiguous, the default): four lines `class: light` / `ask:` / `check: <command> -> pass when` / `scope:`. **full** (feature, refactor, new flow, schema or migration, auth or permissions, money, paid model calls): run the `jstack:preflight` skill; it writes budgets, runnable acceptance checks and a scope fence and appends the checks to `.agent/brief.md`. Edits under migrations, auth, payments or model-call paths are full whatever the branch says. Stay inside the OWNED paths.
- First step: copy every item of this brief into `<worktree>/.agent/brief.md` as `- [ ] <item>` lines. Tick each one (`- [x] <item>: <evidence>`) as you finish it. An item you didn't do stays unticked, and you say why in the report.
- Work in your own worktree (`bash {{JSTACK_TOOLS}}/new-worktree.sh <branch> --install`), never in the main checkout. It links the shared dependencies; never run a plain install there. After you add, remove or update a library, run `node {{JSTACK_TOOLS}}/worktree-deps.mjs deps`: it gives your worktree its own install. Everything is shared by default and you decide when you need your own copy: `worktree-deps.mjs own deps` or `own generated` (for example after a schema change), `share deps|generated` to go back. The shared store is never written. Remove a finished worktree only with `node {{JSTACK_TOOLS}}/worktree-deps.mjs remove <path> --delete-branch`; a bare `git worktree remove` follows the junctions and deletes the shared stores.
- You never run a production build. Prove your work with your tests (`{{TEST_CMD}}`, local test resources only) and ONE typecheck in the typecheck lane before READY: `source {{JSTACK_TOOLS}}/heavy-lock.sh; tc_run "{{TYPECHECK_CMD}}"` (its own few parallel slots, capped, separate from the train's heavy slot). Never run a typecheck outside the lane.
- Memory: first thing, `echo "<your name>: <task>" > .agent` in your worktree (ignored by git; `mem_map` uses it to say which processes are yours). One server at a time. Kill everything you start (servers, `tail -f`, loops, browsers) before you report. Close your browser as soon as you've seen what you needed; keep it open only when the owner asked, and mark it: `echo "<why>" > ~/.jstack/keep-browser/<pid of the browser or its launcher>` (expires after 1 hour). Before any other heavy step, `mem_guard`.
- Screenshots and visual checks run on the component gallery (`{{GALLERY_CMD}}`), not on a production build. Close the gallery server and the browser after every run. Live tests happen on the integration deploy after the merge. The one exception is a pre-merge proof that must run your branch's built code: ask the main session first, then one build, inside the slot and capped (`heavy_acquire <name>; heavy_capped "{{BUILD_CMD}}"; heavy_release`).
- Only builds and typechecks hold the slot. Before starting any server, run `source {{JSTACK_TOOLS}}/heavy-lock.sh; server_wait {{MIN_FREE_GB}}` (waits until no build holds the slot and {{MIN_FREE_GB}} GB RAM is free). Avoid hot-reload dev servers. Stop your server and browser right after each test, before editing code.
- Commit atomically (Conventional Commits). Never push, open a PR or merge. Never use `git stash` / `git stash pop`: the stash stack is shared by every worktree; set work aside with a WIP commit.
- Write the PR body from `{{PR_TEMPLATE}}` to `artifacts/pr-body.md` (untracked).
- User-facing UI: READY only with screenshots, a layout and contrast (WCAG AA) check at zero findings, and the current UI unchanged with your feature flag off. New design: stop after the screenshots and report to the main session; send READY only after it says the owner approved.
- Commit as you go, not at the end. If you own a CHAIN of tickets, build them in order on one stacked branch and send READY after each ticket, then keep going on the next one.
- Before READY on a **full** (or light with domains) pre-flight, run `/unslop --base origin/{{INTEGRATION_BRANCH}} --fix` on your diff without waiting to be asked: fix or explain every CONFIRMED finding (UI design, outward and data-deleting fixes stop at propose), and put the report path and the one-line counts in your READY message. A quick class skips it; the READY gate's fast scan still runs. Then record what you learned: `node {{JSTACK_TOOLS}}/memory/memory.mjs add ...` for a decision the next agent must not re-decide (only when the repo has `.jstack/`).
- Before READY, run `bash {{JSTACK_TOOLS}}/ready-gate.sh <worktree> --base origin/{{INTEGRATION_BRANCH}}` (it runs the typecheck through `tc_run` for you) until it prints `READY accepted`. The orchestrator runs it again before boarding you.
- If a jstack guard hook denies a command, run the retry it gives you, exactly. Don't rename, split or wrap the command to get around it.
- When ready, send exactly `READY FOR BUILD: <worktree path> - <PR title> - typecheck green at <sha>` via SendMessage to: '<orchestrator id>', where `<sha>` is your branch head (commit everything first, nothing committed after the typecheck). Without that line, or when your head moved past it, the train replies "typecheck first" and does not board you. If the train's integration typecheck points at your files, it drops your branch and sends you the error lines: fix, typecheck in the lane, READY again. You board the next train; nobody waits for you. Then report to the main session in under 150 words.
