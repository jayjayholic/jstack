# Sources: LLM cost, metering, keys and caching

Carried over from the research pass of 2026-10-25 (`02-research-llm-cost.md`), product-specific lines removed. Each line keeps the tag it had there: **[V]** checked against the primary page in that pass; **[K]**, **[B]**, **[C]** or **[M]** a known citation (author, year, venue) not re-opened; **[U]** unverified, treat as a hypothesis. Lines without a tag were cited with their venue and date only.

- S1 - OWASP Top 10 for LLM Applications, **LLM10:2025 Unbounded Consumption** (genai.owasp.org/llmrisk/llm102025-unbounded-consumption) - 2025 - [V] - input size limits, quotas, timeouts, anomaly detection, queued-action caps
- S2 - OWASP **File Upload Cheat Sheet** (cheatsheetseries.owasp.org) - living - [V] - limit the *decompressed* size, extension allow-list, zip bombs
- S3 - Google SRE Book ch. 21 **"Handling Overload"** (A. Forero Cuervo), O'Reilly - 2016 - [V] - per-customer quotas, criticality, retry budget (3 attempts per request, retries under 10% per client)
- S4 - Google SRE Workbook **"Alerting on SLOs"** (multiwindow, multi-burn-rate) - 2018 - [V] - burn-rate alerts 14.4 / 6 / 1 on 1h / 6h / 3d windows, each paired with a short window
- S5 - M. Brooker, **"Timeouts, retries and backoff with jitter"**, Amazon Builders' Library - 2019 - [V] - token-bucket retry budget, retry at one layer only, retry only idempotent calls
- S6 - J. Chhabra, **"Caching challenges and strategies"**, Amazon Builders' Library - 2019 - [V] - soft/hard TTL, negative caching, request coalescing, a TTL chosen on purpose
- S7 - Brandur Leach, **"Implementing Stripe-like Idempotency Keys in Postgres"** (brandur.org, 2017-10-27) - 2017 - [V] - idempotency keys, recovery points, foreign state mutations. Note: here the key is generated once per *logical request* and **reused across client retries**; it does not say "one key per attempt" (that metering choice is ours, see F2)
- S8 - Anthropic, **Prompt caching** docs (platform.claude.com/docs/en/build-with-claude/prompt-caching) - 2026 - [V] re-read 2026-10-26 - request-level `cache_control` (automatic caching) "applies the cache breakpoint to the last cacheable block"; prefix order `tools` -> `system` -> `messages`, a change at one level invalidates it and every later level; minimum cacheable length per model (512, 1,024, 2,048 or 4,096 tokens), "Shorter prompts cannot be cached, even if marked", processed without caching and no error; writes 1.25x base input (5-minute TTL) or 2x (1-hour TTL), reads 0.1x (some models lower); `usage.cache_creation.ephemeral_5m_input_tokens` / `ephemeral_1h_input_tokens` sum to `cache_creation_input_tokens`; 20-position lookback per breakpoint; unstable JSON key order breaks caches; a cache entry is readable only after the first response starts (parallel calls each write)
- S9 - OpenAI, **Prompt caching** guide (developers.openai.com/api/docs/guides/prompt-caching) - 2026 - [V] re-read 2026-10-26 - minimum 1,024 tokens on current models; `cached_tokens` counts billed reads, writes reported apart as `cache_write_tokens`; writes 1.25x (30 min) or 2.5x (12 h) on current models, reads 0.1x; `prompt_cache_key`; static content first, timestamps and user-specific content last
- S10 - Anthropic, **Token counting** + **Message Batches** docs (platform.claude.com) - 2026 - [V] - free `count_tokens` estimate before sending, batch at 50% price
- S11 - Vercel, **AI Gateway BYOK** docs (vercel.com/docs/ai-gateway/authentication-and-byok/byok, updated 2026-09-22) - 2026 - [V] - *a failed BYOK request falls back to system credentials, billed to credits*, BYOK spend excluded from budgets, request-scoped `providerOptions.gateway.byok`
- S12 - OpenTelemetry **GenAI semantic conventions** (`gen_ai.usage.input_tokens`, `gen_ai.usage.cache_read.input_tokens`, `gen_ai.usage.cache_creation.input_tokens`, `gen_ai.provider.name`, `gen_ai.request.model`; status *Development*) - 2025–26 - [V] attribute names and the Anthropic mapping (opentelemetry.io/docs/specs/semconv/gen-ai/anthropic). The `gen_ai.client.token.usage` metric shape is [U] - vendor-neutral usage schema. The Anthropic page says `gen_ai.usage.input_tokens = input_tokens + cache_read_input_tokens + cache_creation_input_tokens`, so normalise. Some third-party backends treat cache reads as a subset instead; check yours
- S13 - Saltzer & Schroeder, **"The Protection of Information in Computer Systems"**, Proc. IEEE 63(9):1278–1308 - 1975 - [V] citation - *fail-safe defaults*: decide on permission, not exclusion
- S14 - MITRE **CWE-636 "Not Failing Securely ('Failing Open')"** and **CWE-367 TOCTOU** - living - [C] - a spend gate that allows on error; a limit checked against a stale copy
- S15 - NIST **SP 800-57 Part 1 Rev. 5** (E. Barker) - May 2020 - [V] citation - key inventory, cryptoperiod, key states (states list via SP 800-152 glossary)
- S16 - Chen, Zaharia, Zou, **FrugalGPT** arXiv:2305.05176 - 2023 - [V] - LLM cascade, prompt adaptation, approximation (cache). Claims up to 98% cost cut at GPT-4 quality
- S17 - Ong et al., **RouteLLM** arXiv:2406.18665 - 2024 (v4 Feb 2025) - [V] - learned router between strong and weak models; abstract claims costs cut "by over 2 times *in certain cases*". arXiv lists no venue; any peer-reviewed venue is [U]
- S18 - G. Klein, **"Performing a Project Premortem"**, HBR 85(9) - Sep 2007 - [V] citation - imagine the spend incident before building
- S19 - Kohavi, Tang, Xu, *Trustworthy Online Controlled Experiments*, Cambridge UP - 2020 - [C] - power analysis and sample-size estimate before running, guardrail metrics
- S20 - J. D. C. Little, "A Proof for the Queuing Formula L = λW", *Operations Research* 9(3) - 1961 - [C] - items in flight L = arrival rate λ × time in system W, so spend in flight ≈ L × cost per item (only for a running stream, not for a one-job estimate)
- S21 - Meyer, "Applying Design by Contract", *IEEE Computer* 25(10) - 1992 - [C] - preconditions on the call boundary (metered client as the only door)
- S22 - Claessen & Hughes, "QuickCheck", ICFP - 2000 - [C] - property tests: every attempt emits exactly one usage event

- S24 - Gawande, *The Checklist Manifesto* - 2009 - [C] - DO-CONFIRM pre-flight list
- S25 - Anthropic, "Building effective agents" - Dec 2024 - [C] - start simple, add steps only when measured
- S26 - Anthropic, **Context editing** docs (platform.claude.com/docs/en/build-with-claude/context-editing) - 2026 - [V] 2026-10-26 - tool-result clearing "Invalidates cached prompt prefixes when content is cleared"; `clear_at_least` "Ensures a minimum number of tokens is cleared each time the strategy activates ... helps determine if context clearing is worth breaking your prompt cache"; `trigger` (default 100,000 input tokens) and `keep` (default 3 tool uses). The basis for clearing with hysteresis
- S27 - Break-even of a cache write, derived from S8's multipliers: a 5-minute write costs 0.25x extra and each read saves 0.9x, so reads per written token must exceed 0.25 / 0.9 = 0.28; a 1-hour write needs 1 / 0.9 = 1.11. Models with cheaper reads move it slightly lower. `tools/unslop/cache-probe.mjs` uses it
- Static scan for bypasses: `rg -n "new (Anthropic|OpenAI|Mistral|GoogleGenAI)\(|from ['\"](@anthropic-ai/sdk|openai|@mistralai|@google/genai|@ai-sdk/)|https://api\.(openai|anthropic|deepinfra|mistral|assemblyai|groq)\." --glob '!<your-metered-client-dir>/**'` (adapt the provider list and glob). Any hit outside the choke point fails the check. Make the import half a CI lint rule (ESLint `no-restricted-imports`); that rule does not catch raw provider URLs, so keep the URL grep (or a `no-restricted-syntax` rule) for those. Repeat for Python (`import anthropic`, `from openai`) if present.
- Normalisation test: an Anthropic response with `cache_read_input_tokens=1800, input_tokens=248` must store total input 2048 (S8, S12 note).
