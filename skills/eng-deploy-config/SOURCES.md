- **Method: (a) a regression test pinned to the feature, so a merge that drops it turns CI red; (b) consumer-driven contract tests against each real client's expectations; (c) conformance to the published protocol spec.** S2 (deployment pipeline: every commit goes through the same tests). S28 (contract tests). S19/S20: MCP clients discover auth through RFC 9728 protected-resource metadata → AS metadata (RFC 8414, or OpenID Connect Discovery from 2025-11-25) → client registration (pre-registered, Client ID Metadata Document, or RFC 7591 DCR), so every one of those endpoints is part of the contract. The exact MUSTs changed between spec revisions, so the probe must target the revision the server declares.
- `curl -si -X POST -H 'Content-Type: application/json' -d '{}' $URL/mcp` (no token) → `401`. Record the `WWW-Authenticate` header: under 2025-06-18 it MUST be present; under 2025-11-25 either it carries `resource_metadata=` **or** the well-known URI below must exist.
- `curl -s <AS>/.well-known/oauth-authorization-server` (or `/.well-known/openid-configuration`, path-inserted for issuers with a path) → has `authorization_endpoint`, `token_endpoint`, `code_challenge_methods_supported` (2025-11-25 clients refuse to proceed without it), and either `registration_endpoint` or `client_id_metadata_document_supported` for clients that are not pre-registered.
- **Method: expand → migrate → contract (Parallel Change, S13), where *contract* is a tracked step with its own definition of done.** Use strangler-fig routing for UI (S14). Every release toggle gets a removal date (S8, S10 clean-up practices), with automated stale-flag deletion where possible (S11). Knight Capital (S12) is the canonical loss: Power Peg code unused since 2003 was left in place, its flag was repurposed for new code, one of eight servers missed the new deploy, and the old code ran again (>$460M).
